# Demo Script

Portable markdown module for workbook artifact `6.1 Demo Script`.

## Purpose

Script the demo that proves the outcome claimed in the `PR-FAQ` and `Positioning Canvas`, so the `Release Article`, live sales demo path, and `Lightning Strike` all draw from one verified, reusable demo instead of each team improvising its own.

## Core rule

The demo proves the customer outcome, not a feature tour. If the script can be summarized as "click through the UI," it is not ready.

## Non-negotiables

- Do not script until `Certification Rubric` status is `Certified` — same gate as `Release Article`.
- Tier 3 releases do not get a Demo Script; fold into the `Monthly Innovation Roundup` as a screenshot or GIF at most.
- Open on the customer's problem or status quo, never the login screen or product homepage.
- Runtime target: 60-90 seconds for a Tier 2 release, up to 3 minutes for a Tier 1 flagship — cut anything longer.
- Every number or result shown on screen must be real product output; no mocked or invented data.
- Produce one script with a cut list; do not write three separate scripts for the full version, the social cut, and the live sales demo.

## Required sections

- `Release Name`
- `Launch Tier`
- `Runtime Target`
- `Cold Open (Customer Problem)`
- `Demo Flow`
- `Payoff Moment`
- `Close & CTA`
- `Cut List`
- `Next Required Artifact`

## Inputs

- `START HERE` (Q1-Q4)
- `PR-FAQ Template`
- `Positioning Canvas`
- `Certification Rubric` (status must be `Certified`)
- `Battle Cards`

## Instructions

1. Confirm `Certification Rubric` status is `Certified` before scripting anything. If not certified, stop and name the blocking dimension.
2. If `Launch Tier` is `Tier 3`, stop and route to the `Monthly Innovation Roundup` instead of scripting a standalone demo.
3. Write the `Cold Open` from the customer's status quo (`START HERE` Q3), not the product UI.
4. Write the `Demo Flow` as numbered steps; each step names the action taken and the specific claim it proves.
5. Identify one `Payoff Moment` — the single beat that makes the outcome undeniable — and place it deliberately, not buried mid-flow.
6. Verify every on-screen number or result is real product output, not a mock; flag anything not yet real as unresolved.
7. Write the `Cut List` showing how to trim the same script for the full version, a social cut, and the live sales demo path.

## Output

Return:

- `Release Name`
- `Launch Tier`
- `Runtime Target`
- `Cold Open`
- `Demo Flow`
- `Payoff Moment`
- `Close & CTA`
- `Cut List`
- `Unresolved Claims`
- `Next Required Artifact`

## Handoff

Feeds:

- `Release Article` (full cut embeds in `How It Works`)
- `Battle Cards` (live sales demo path)
- `Stage Gate Architecture` (Lightning Strike asset checklist)
