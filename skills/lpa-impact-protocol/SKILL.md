# Impact Protocol

Portable markdown module for workbook artifact `5.2 Impact Protocol`.

## Purpose

Specify how launch impact will actually be measured after deployment and launch.

## Measurement philosophy

- Define success before launch.
- Combine `Spock` data and `Oprah` data.
- Eradicate vanity metrics.

## Section order

1. `SECTION 1 — METRIC TREE`
2. `Lagging Indicator`
3. `North Star Metric`
4. `Leading Indicators`
5. `Guardrail Metrics`
6. `PHASE 1 — PRE-LAUNCH`
7. `PHASE 2 — LAUNCH`
8. `PHASE 3 — POST-LAUNCH`

## Non-negotiables

- Every launch needs a metric tree before development begins.
- Measure value delivered to the customer, not only value captured by the business.
- Guardrails are mandatory so metrics cannot be gamed.
- Baselines must exist before launch or impact cannot be proven.
- Each readout needs a decision path, not just a dashboard.

- `24-hour Readout`
