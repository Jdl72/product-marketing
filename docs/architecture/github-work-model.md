# GitHub Work Model

## GitHub equivalents

- `Epic` -> parent GitHub issue
- `Story / task` -> child GitHub issue
- `Roadmap board` -> GitHub Project
- `Release bucket` -> milestone
- `Work type` -> label

## Recommended labels

- `epic`
- `agent`
- `skill`
- `schema`
- `artifact`
- `retrieval`
- `workflow`
- `eval`
- `docs`
- `infra`
- `research`
- `sales-enablement`
- `gtm`
- `campaign-support`
- `priority:high`
- `priority:medium`
- `priority:low`

## Recommended milestones

- `M1 Method OS`
- `M2 Human-in-the-loop Workspace`
- `M3 Evidence Layer`
- `M4 Strategy Orchestrator`
- `M5 Asset and Campaign Operations`

## Recommended multi-client epics

Add these cross-cutting epics when the system moves from a single workspace to reusable consulting use:

- `Epic: Core PMM System Hardening`
- `Epic: Client Configuration Framework`
- `Epic: Cross-Functional Operating Rhythm`

Treat client-specific implementations such as [client] as consumer backlogs rather than permanent core epics.

## Epic issue structure

Each epic issue should contain:

- goal
- user jobs covered
- system responsibilities
- required inputs
- outputs and artifacts
- dependencies
- checklist of child issues

## Child issue structure

Each child issue should contain:

- problem
- target user job
- scope
- deliverable
- dependencies
- acceptance criteria

## Recommended GitHub Project fields

- `Status`
  Todo, In Progress, In Review, Done
- `Milestone`
- `Epic`
- `Layer`
  Method, Artifact, System, Evaluation
- `Priority`
- `Area`
  Market Intelligence, Positioning, GTM, Sales Enablement, Campaign Support
